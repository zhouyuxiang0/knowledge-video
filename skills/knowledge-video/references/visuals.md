# 画面组织与验证

沿用当前 PixiJS + JavaScript 路线，根据本镜表达安排场景插画、角色动作、机制图解、资料图或局部空间效果。对话需要看清角色关系与反应，机制需要看清条件变化与结果；不因现有模板方便而让整片都使用同一构图。

- 主体动作承担叙事：开始、过程、接触和结果都可辨。整图推拉、漂浮或装饰粒子不能代替人物行动。
- 用同一对象推演关键条件，必要时改变景别突出手、道具和结果。近景必须新增信息；关键因果不能藏在小字或远处。
- 机制状态、方向与标记使用场景时间和同一份数据；示意图不冒充实验结果。相机改变的是观看位置，不能暗示不存在的物理原因。
- 字幕、标签与主体共享安全区。检查相机运动中段、切前末帧和标签相遇时刻，避免遮住手、脸、接触点或重要文字。必须同时读的文字应留足阅读时间。
- 人物、背景、色彩和线条保持一致。原画与绑定检查见 [character-motion.md](character-motion.md)，素材分层见 [images.md](images.md)。

## Validate an approach borrowed from a reference

先实际观看参考片，记录片段与可观察方法，区分“看到了什么”和“猜测观众会有什么反应”。参考的播放或点赞数据不能证明某种画法有效。

在本期代表性连续样段中检验适用方法，覆盖关键反应、机制变化与实际切镜。比较画面方法时尽量保持同一文稿、旁白与时长，避免为了试风格制作两套整片。

按目标展示尺寸检查：处境是否清楚，动作与结果是否看得见，注意力是否跟随解释，文字是否来得及读，画风是否一致，是否改错科学含义。记录文件摘要、观看范围、实际缺陷与修复结果，再决定是否扩展。静帧支持构图判断，原速连续播放支持动作与节奏判断；受众效果和用户接受另记。
