# 本地配音和低内存运行

在选用本地模型、出现内存压力、长文生成中断时读取。这里描述方法，不指定所有项目都使用同一个模型，也不携带参考音色或模型权重。

- 先确认当前硬件、磁盘余量、模型/编解码器版本、实际后端和生成限制。磁盘上的权重大小不能当作推理峰值；Mac 统一内存还供系统和其他应用使用。
- 使用用户有权使用的参考录音。参考声、参考文字、文稿、模型版本、采样参数及表达提示共同构成缓存身份；只复用摘要和条件一致的完整结果。
- 短样覆盖实际文稿中的长句、数字、专名、转折与停顿。短样可用于选择方案，不能证明全文的峰值或听感。
- 可分别用独立进程做参考编码、全文 token 生成和连续解码，让上一阶段退出后再启动下一阶段。需要全文一次合成时，完整文字仍进入一次底层生成调用，不能偷换成逐句配音。
- 解码内存不足时先保存并校验完整编码。后端支持有状态流式解码时，在一个持续会话内处理，核对编码及采样完整覆盖；用短范围全量/流式输出对照验证，不因解码分块重新生成正文。
- 删除未使用的模型分支只适用于已核对的模型版本和执行路径。必须先证明该分支确实不参与当前任务，并做输出等价对照；不把一次优化变成通用模型补丁。
- 在父进程监控子进程实际内存、系统压力和交换空间；运行前保留系统余量，超限只停止自己的任务并保留有效中间结果。缓存限制、框架软上限和采样监控都不是内核硬隔离，阶段预算应由目标机器实测决定。
- 串行安排模型和重渲染，复用已验证中间结果。用户仍需要其他应用时，不能擅自结束它们，也不通过关闭系统保护来“跑通”。
- 运行结束核对原生结束标志、完整文本覆盖、有限采样值、音频回读、尾音及实际听感。ASR 可定位漏字疑点，不能替代声调、语气和停顿听辨。

一些后端支持原生语速或表达控制，另一些不支持。先查当前实现，不编造参数；把提示与朗读正文分开。优先让镜头跟随已接受音频，不靠后期人声拉伸解决时长问题。更换模型或提示后重新验证全文，不继承旧音频的接受结论。
